# نشر الموقع على GitHub Pages

## تصحيح مهم
النسخة السابقة كانت تفترض أن كل الملفات يجب أن تكون في جذر المستودع بدون
مجلدات (flat structure). **هذا غير صحيح** — GitHub Pages يدعم المجلدات
الفرعية (`css/`, `js/`, `assets/`) بشكل طبيعي تماماً، ولا داعي لتفكيك
بنية المشروع. البنية المنظمة هنا أفضل للصيانة وأسهل للتطوير المستقبلي.

## خطوات النشر (صحيحة ومختبرة)

1. أنشئي مستودعاً جديداً على GitHub باسم مثلاً `ENGLISH-CLUB`.
2. ارفعي **محتوى هذا المجلد بالكامل** (بما فيه مجلدات `css/`, `js/`, `assets/`)
   إلى جذر المستودع — حافظي على بنية المجلدات كما هي.
3. تأكدي أن `index.html` موجود في جذر المستودع (وليس داخل مجلد فرعي آخر).
4. من إعدادات المستودع: **Settings → Pages → Source: Deploy from a branch
   → Branch: main → Folder: / (root)** → Save.
5. بعد بضع دقائق، الموقع يكون متاحاً على:
   `https://<اسم-المستخدم>.github.io/ENGLISH-CLUB/`
6. بعد أي تعديل مستقبلي، اعملي تحديث قوي للمتصفح (Ctrl+F5 أو Cmd+Shift+R)
   لتفادي النسخة المخزّنة مؤقتاً (cache) في المتصفح أو الـ Service Worker.

## ملاحظة حول قاعدة البيانات المحلية
الموقع يستخدم IndexedDB (محلي في متصفح كل زائر). هذا يعني:
- بيانات كل مستخدم (نقاطه، تسجيلاته) محفوظة في متصفحه/جهازه فقط.
- لا يوجد مزامنة تلقائية بين الأجهزة (هذا مطابق لتصميم "المرحلة الأولى"
  الموضّح في وثيقة المتطلبات — الترقية لقاعدة بيانات سحابية مشتركة
  تتطلب المرحلة الثانية: Firebase أو Supabase).

## أمان لوحة الإدارة
راجعي `js/config.js` (إيميلات المشرفين الثلاثة) و `js/firebase-config.js`
(اختياري، لتفعيل مصادقة حقيقية عبر خوادم Google) قبل نشر لوحة `admin.html`.
